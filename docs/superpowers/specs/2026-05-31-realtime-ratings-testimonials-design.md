# Real-Time Ratings & Testimonials System

**Date:** 2026-05-31
**Status:** Approved
**Database:** Turso (libSQL)

## Summary

Leverage ratings generated by users at the end of each support conversation to display real-time social proof on the Home page, increasing visitor trust and conversion.

---

## 1. Database Schema

### New table: `ratings`

```sql
CREATE TABLE IF NOT EXISTS ratings (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  conversation_id INTEGER NOT NULL UNIQUE,
  customer_name VARCHAR(150) NOT NULL,
  customer_country VARCHAR(100) NOT NULL,
  rating INTEGER NOT NULL CHECK(rating >= 1 AND rating <= 5),
  comment TEXT DEFAULT '',
  resolved INTEGER DEFAULT 1,
  first_response_time_ms INTEGER DEFAULT NULL,  -- Denormalized at submission time for fast stats queries
  created_at TEXT DEFAULT (datetime('now')),
  updated_at TEXT DEFAULT (datetime('now'))
);

CREATE INDEX idx_ratings_created_at ON ratings(created_at DESC);
CREATE INDEX idx_ratings_rating ON ratings(rating);
CREATE INDEX idx_ratings_conversation_id ON ratings(conversation_id);
```

### Migration: `021_conversation_response_time.sql`

```sql
ALTER TABLE conversations ADD COLUMN first_agent_response_at TEXT DEFAULT NULL;
```

### Rules

- One rating per conversation (UNIQUE on `conversation_id`)
- Rating is mandatory (1-5)
- Comment is optional
- Stored immediately after chat close
- Available for real-time queries

## 2. API Routes

### `POST /api/ratings`

Submit a new rating.

**Body:**
```json
{
  "conversation_id": 123,
  "customer_name": "Anthony Rivera",
  "customer_country": "Colombia",
  "rating": 5,
  "comment": "Excelente atención"
}
```

**Validation:**
- Conversation must exist and have status `closed`
- No duplicate rating for same conversation
- Rating must be 1-5
- Name max 150 chars, country max 100 chars
- Comment auto-filtered (profanity, spam, URLs)

**Response:** `201 Created` with rating object.

### `GET /api/ratings`

Get latest 10 ratings for the Home page carousel.

**No auth required** (public endpoint).

**Response:**
```json
{
  "ratings": [
    {
      "id": 1,
      "customer_name": "Anthony Rivera",
      "customer_country": "Colombia",
      "rating": 5,
      "comment": "Excelente atención...",
      "resolved": 1,
      "created_at": "2026-05-31T10:00:00Z"
    }
  ]
}
```

Ordered by `created_at DESC`, limited to 10.

### `GET /api/ratings/stats`

Aggregate metrics for the stats bar.

**Response:**
```json
{
  "avg_rating": 4.8,
  "total_ratings": 1245,
  "resolved_pct": 98,
  "avg_response_time_ms": 120000
}
```

**Caching:** Results cached for 30 seconds to reduce DB load during polling.

## 3. Chat Integration — Rating Form

### Trigger

When conversation status changes to `closed` (via `POST /api/chat/close` or inactivity).

### Flow

1. ChatWidget polls and detects status = `closed`
2. Check localStorage for `rated_<conversationId>` flag
3. If not rated, show rating form (replacing chat messages view)
4. Form fields:
   - Star selector (1-5, interactive)
   - Name input (required)
   - Country input (required, could be dropdown)
   - Comment textarea (optional)
5. On submit → `POST /api/ratings`
6. Show "Thank you" confirmation
7. Store `rated_<conversationId>: true` in localStorage

### Component Changes

- Modify `ChatWidget.tsx` to detect `closed` status and show `RatingForm` component
- New `RatingForm.tsx` component with star selector, inputs, submit logic

## 5. Real-Time Strategy

**Approach:** Polling (consistent with existing ChatWidget pattern)

- Home page polls `GET /api/ratings` every 15 seconds
- Stats bar polls `GET /api/ratings/stats` every 30 seconds
- Polling stops when tab is not visible (Page Visibility API)
- No WebSockets or SSE (Turso doesn't support subscriptions)

---

## 6. Moderation

**Auto-filter on submission:**
- Profanity word list (English + Spanish)
- Spam patterns (repeated characters, ALL CAPS blocks)
- External URL detection
- SQL injection patterns

**If comment flagged:**
- Rating saved (contributes to metrics)
- Comment stored as empty string
- User sees "Thank you" (no error about moderation)

**No admin moderation UI** — comments are filtered automatically.

## 7. Response Time Tracking

### Recording

In `POST /api/chat/send`, when sender is agent or AI:
- If `conversations.first_agent_response_at IS NULL`
- Set it to current timestamp

### Calculation

At rating submission time, calculate and store `first_response_time_ms` in the ratings table (denormalized for fast queries):

```sql
-- At submission time:
SELECT (julianday(c.first_agent_response_at) - julianday(c.created_at)) * 86400000
FROM conversations c WHERE c.id = ?;
-- Store result in ratings.first_response_time_ms
```

Stats query uses the denormalized value:

```sql
SELECT AVG(first_response_time_ms) AS avg_response_time_ms
FROM ratings
WHERE first_response_time_ms IS NOT NULL;
```

### Display

- < 60s: "X segundos"
- 1-59 min: "X minutos"
- > 60 min: "X horas"

## 10. UX Flow Summary

1. User chats with AI/support agent
2. Conversation closes (resolved, closed by agent, or timeout)
3. ChatWidget shows rating form
4. User submits rating (name, country, stars, optional comment)
5. Rating stored in Turso `ratings` table
6. Home page polls and picks up new rating within 15s
7. Carousel updates with new testimonial
8. Stats bar recalculates averages
9. New visitors see fresh, real testimonials in real-time
