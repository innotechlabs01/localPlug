# API Validation — Real Endpoint Contracts

> Real contracts read from the current route handlers. Events emitted are inline today (see EVENT_TRACEABILITY.md) — they become typed in 2C.

Legend for Permissions column:
- `requirePermission(<domain>, <action>)` — admin RBAC via `lib/admin/permissions`
- `auth()` — Clerk server `clerkId` check
- `requireWebhookAuth` — `lib/webhook-auth` shared secret
- `signature: x-evolution-signature` / `paddle-signature` / `x-n8n-signature` — webhook HMAC/secret check
- `CRON_SECRET` / `x-vercel-cron` — cron auth
- `rateLimitMiddleware` — generic rate limit
- `public` — no auth

## Ambiguous / Notable

- **All `app/api/geocode`, `app/api/config`** read configuration from a config store but the underlying config tables/columns are not fully visible from these handlers alone (config resolved via `lib/config` / `lib/pricing`) — flagged as config-source-dependent but contracts otherwise clear.
- **`app/api/bookings/driver-assigned` & `app/api/bookings/delivery-completed`** emit *no* DB writes in this repo — they only call n8n (`triggerDriverAssigned` / `triggerDeliveryCompleted`). Any order/notification side effects live inside the n8n workflow, not in this handler. Listed as "none — n8n side-effect".
- **`app/api/cron/process-queue`** interacts with the queue store (`lib/queue/message-queue`, `lib/queue/whatsapp-worker`) rather than named SQL tables; the concrete table for the message queue is not directly visible in this route. Marked `queue store`.
- No endpoint in the requested set had an *indeterminate* Input/Output from the code itself; every row above was read directly from the handler. The only ambiguity is the externalized side effects (n8n workflows, queue store internals).
